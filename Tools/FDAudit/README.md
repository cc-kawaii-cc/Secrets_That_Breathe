# FD read-only model audit — 2026-10-26

Inspected both `Assets/Model Palm/FD V.2/FD.fbx` and `Assets/Model Palm/FD/FD2.fbx`. No model, prefab, importer or material was changed. Only these audit scripts, JSON reports and diagnostic images were generated.

FD V.2: 8 mesh objects, 15,920 source control points, 30,624 triangles counted as sum(polygon vertices − 2). Body accounts for 27,203 triangles. The previous FD has 15 mesh objects and 30,339 triangles, including separate Headlight and Tail_light nodes. V.2 consolidates the lights into one Light node (920 vertices, 1,648 triangles). Its 12 disconnected components comprise six front elements, four rear elements and two side markers, classified by measured bounds. See `light_components.json`.

Body and Light in V.2 use the same `tripo_mat_2fc8db08` material and 4096-square atlas. Its emission is black, Emission Map is empty and Normal Map is empty. Consequently, enabling emission on that shared material would also affect the body. A separate light material with a selective UV mask, or newly built simple emissive surfaces inside the existing housings, is appropriate. A mask is the smaller change; separate clean geometry gives more control when the original lens surface is uneven. Housing, glass and reflectors should stay non-emissive.

The neutral diagnostic views show fairly smooth broad hood and roof panels. More obvious uneven geometry/faceting appears around bumper recesses, headlight surfaces, wheel-arch borders and some panel transitions. The texture also carries shadows and highlights, which can add apparent dents and seams. Existing imported corner normals smooth the large panels; a blanket normals recalculation or subdivision has not been tested and cannot be assumed to fix the detailed regions. Repairing the whole car is a larger task than adding selected light emission.

`front_comparison.png`, `hood_comparison.png` and `rear_comparison.png` each compare: original atlas without lighting; neutral material with source corner normals; face normals; and triangulation. Images are CPU orthographic diagnostic projections of the actual FBX data, not Unity/Blender screenshots. FBX polygons are fan-triangulated for inspection; concave n-gons may differ from Unity's triangulation. Window/wheel materials are placeholders in these images. They are suitable for assessing body/lens shapes, not final material appearance.

Not checked: runtime Unity rendering, alternate normals imports, Blender edit history/modifiers, precise light color areas, full UV overlap/stretch analysis, collision, exported replacement assets or shader/Bloom behavior. The count refers to the supplied FBX geometry, with no new modifiers. The assessment supports emission feasibility and identifies areas for closer repair; it is not a complete game-ready asset certification.
